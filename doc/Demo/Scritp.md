# LifeSOS: recommended capture plan

Make the video tell one story, not demonstrate every feature.

The strongest story is:

Lumi starts healthy → LifeSOS detects a hidden life trade-off → Muse Spark interprets it → the user takes action → Lumi recovers.

That is the product. The four data channels, connectors, settings, and architecture support the story, but they should not compete with it.

I reviewed the repository's current `demo-script.md` and `final-checklist.md`. They already specify a 60-second primary flow and seven screenshots. I would keep that structure, with a few presentation refinements below.&#x20;

## 1. The main video: 60–90 seconds

Record in portrait orientation, using the actual app on the phone. Use a clean screen recording with a clear voice-over. Avoid a long introduction, developer desktop footage, or a tour of every settings page.

### Video sequence

| Time      | What to capture                                                        | What the viewer should understand                                                                                                                 |
| --------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0–7 sec   | Home screen, Lumi Radiant ✨                                            | Meet the companion. Let viewers see her before anything goes wrong.                                                                               |
| 7–15 sec  | Open the science menu and select Success Trap                          | Introduce the cross-channel conflict.                                                                                                             |
| 15–33 sec | Tap Consult LifeSOS for Advice. Show the completed diagnosis.             | High productivity and savings look good, but sleep and relationships are suffering. Show the actual Muse Spark response and its model provenance. |
| 33–42 sec | Tap the WhatsApp nudge                                                 | The insight becomes a practical action, not just another dashboard warning.                                                                       |
| 42–56 sec | Return to LifeSOS, log follow-through, then play Lumi's voice readout | The user acts, logs the action, and Lumi returns to Radiant.                                                                                      |
| 56–68 sec | Open Show Data                                                         | Show the four-channel bio-radar: Health, Tasks, Finance, Social.                                                                                  |
| 68–78 sec | Briefly show Connections, then return Home                             | Show that LifeSOS connects multiple sources, and end on Lumi.                                                                                    |

The main attraction is the Success Trap scenario. The README describes it clearly: 98% task completion and increased savings alongside reduced sleep and canceled social plans.&#x20;

Important: Call it a preconfigured demo scenario in the narration. Don't imply that those scenario numbers are the presenter's actual live personal data. ### 2. Narration I would use

Here is the voice-over I'd recommend. It is written to sound like a product introduction rather than a developer explaining code.

> Your fitness tracker knows your steps. Your calendar knows your schedule. Your bank knows your spending.
>
> But none of them sees the trade-offs between them.
>
> Meet Lumi. She's the living companion inside LifeSOS.
>
> In this Success Trap scenario, productivity is high and savings are up. But sleep is falling, and important relationships are being neglected.
>
> LifeSOS connects those signals. Its life-state engine detects the conflict, and Meta Muse Spark turns it into an empathetic, actionable response.
>
> Lumi doesn't just tell you something is wrong. She helps you do something about it.
>
> One tap prepares a message to reconnect. After follow-through is logged, Lumi returns to Radiant.
>
> LifeSOS: a companion that looks across your life, not just one metric.

I would let Lumi's actual TTS readout be heard during the recovery scene. Keep the narration quiet or pause it while she speaks. That is a memorable moment.

## 4. Prepare the phone before recording

Do this once, then record the whole sequence.

- Use the Meta Horizon theme and light appearance.
- Enable Do Not Disturb. Clear notifications and close unrelated apps.
- Set a comfortable, consistent screen brightness.
- Have the Meta Model API key already entered. Do not record the key-entry process.
- Test one real Consult LifeSOS for Advice response before recording.
- Confirm the response displays the actual Muse Spark model attribution.
- Confirm the WhatsApp link opens and has the message pre-filled.
- Make sure the voice readout is audible in the recording setup.
- Relaunch the app into the Radiant Home state.

Use the live Muse Spark path for the main video. Keep the offline Rules Engine path as a separate backup demonstration; don't switch between the two in the middle of the primary story. The project's own demo script makes this distinction for a good reason.&#x20;

## 5. Capture quality

Video: Portrait, native device resolution, ideally at least 1080 pixels wide and 30 fps. Use Android's built-in screen recorder, enabling device audio and microphone where available. Test a short recording first to confirm that Lumi's TTS is actually audible. If the recorder cannot capture it, add the voice-over separately and preserve the actual app footage.

Record a continuous take if possible. Leave a small pause after each tap, let animations complete, and leave the Spark diagnosis on screen long enough to read. Trim waiting time and accidental gestures afterward. Avoid elaborate transitions, heavy background music, or a talking-head introduction.

Screenshots: Capture actual PNGs at device resolution. Do not recreate screens in a graphics editor or paste UI elements together. Crop only to remove irrelevant status-bar clutter or private information; retain the app's real layout.

For example, using ADB:

```
mkdir -p doc/screenshots

adb shell screencap -p /sdcard/01-home-radiant.png
adb pull /sdcard/01-home-radiant.png doc/screenshots/
```

Repeat for each of the seven states, changing the filename each time.

## 6. The README presentation

The README is part of the judging experience. Someone may open the GitHub repository before watching the video.

I would arrange the top of the README like this:

1. LifeSOS title and a one-sentence product description.
2. Demo video link, near the top.
3. One strong Home/Radiant screenshot.
4. The problem: separate apps see separate metrics, but miss the trade-offs.
5. The solution: Lumi and the cross-channel feedback loop.
6. Screenshot gallery with the remaining six images.
7. Architecture, Meta AI integration, privacy, and setup details.

Use relative image paths such as:

```
![Lumi — Radiant](doc/screenshots/01-home-radiant.png)
```

Put the video on YouTube as Unlisted (or Loom) and link it from the README. The repository's runbook also calls for embedding the screenshots and putting the video link near the top.&#x20;
